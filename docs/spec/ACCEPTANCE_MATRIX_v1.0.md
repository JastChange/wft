# WFT 1.0 验收矩阵

> 状态：Approved for Planning
> 目标：每条需求拥有可重复的验证证据。

## 1. 功能验收

| ID | 场景 | 通过标准 | 自动化层级 |
|---|---|---|---|
| AC-001 | 私有配置与节点清单 | 合法 YAML 生成类型化配置；重复节点名、相对私钥路径、并发超范围被拒绝 | 单元/集成 |
| AC-002 | 管理员初始化 | CLI 生成一次性密码；磁盘只出现 Argon2 哈希；登录 Cookie 不包含密码 | 单元/Web |
| AC-003 | 节点选择 | 显式节点、group、tag、全部启用节点得到确定且去重的目标快照 | 单元 |
| AC-004 | 最新脚本快照 | 每次任务 fetch 远端分支一次；记录 commit/Manifest/脚本哈希；全节点使用相同快照 | Git 集成 |
| AC-005 | 缓存脚本授权 | fetch 失败时显示缓存信息；无确认失败；交互确认或参数授权成功并记录 `used_cached_snapshot=true` | Git/CLI 集成 |
| AC-006 | Manifest 门禁 | 路径逃逸、哈希不符、未知解释器、`read_only=false`、不支持 OS 均在任务创建前失败 | 单元 |
| AC-007 | 自动 Host Key | 未知 Host Key 无需人工确认即可连接，并把实际算法/指纹写入节点快照 | SSH 集成 |
| AC-008 | 节点并发与脚本顺序 | 不同节点最多 10 并发；同一节点严格按方案顺序；单脚本失败不阻塞后续脚本或其他节点 | Fake executor/SSH 集成 |
| AC-009 | 超时 | 超时脚本为 `TIMEOUT`，后续脚本继续，远端清理被尝试且结果单独记录 | SSH 集成 |
| AC-010 | 无重试 | SSH/脚本失败只产生一次执行尝试，不自动重试 | 单元/SSH 集成 |
| AC-011 | 安装结论 | 全部通过→PASS；检查发现问题→FAIL；证据不足→INCONCLUSIVE | 单元 |
| AC-012 | 故障诊断语义 | 成功采集证据的任务为 COMPLETED；发现问题不把执行状态改为 FAILED | 单元 |
| AC-013 | CLI 退出码 | 无问题 0；完成且有问题/FAIL/INCONCLUSIVE 1；配置或执行未完成 2 | CLI 集成 |
| AC-014 | Ctrl-C | 已完成节点保留；未完成节点 CANCELLED；任务 CANCELLED；退出码 2；不恢复 | 进程集成（常规取消路径） |
| AC-015 | 崩溃残留识别 | 启动时把遗留 RUNNING 标记 FAILED，不重新调度 | 单元/集成 |
| AC-016 | 文件权威性 | 删除 SQLite 索引后，所有任务/节点/脚本/问题/分析仍可从权威文件读取 | 集成 |
| AC-017 | 原子 JSON | 正常写入不留下 `.partial`；读取器忽略 `.partial`；未知 schema 主版本拒绝读取 | 单元/文件集成 |
| AC-018 | 派生索引 | 增量同步和完整 rebuild 产生相同查询结果；索引失败不修改权威文件 | 集成 |
| AC-019 | Web 只读 | 登录、列表、筛选、实时片段、详情和下载可用；不存在业务写路由 | Web/E2E |
| AC-020 | 下载路径隔离 | 登录用户只能下载任务白名单文件；路径逃逸与任意文件读取被拒绝 | Web 安全测试 |
| AC-021 | Webhook 单次投递 | 符合条件时恰好调用一次；失败记录 FAILED；不存在重试入口 | HTTP Stub |
| AC-022 | AI 手动分析 | 未运行命令不调用 AI；运行后生成结构化中文分析版本和证据引用 | AI Stub/CLI 集成 |
| AC-023 | AI 分块与回退 | 超预算输入被分块；AI 失败不自动重试并生成规则摘要 | AI Stub |
| AC-024 | 问题归并 | 失败检查生成待分类问题；AI 只在同一节点归并并保留来源；可从成功输出发现问题 | 单元/AI Stub |
| AC-025 | Obsidian 导出 | 每问题一篇、每任务一篇索引；重复导出幂等；人工区保留；WFT 不 commit/push | 临时 Git 仓库 E2E |
| AC-026 | Git 冲突 | Vault 工作树冲突时导出失败且不覆盖人工内容 | Git 集成 |
| AC-027 | 删除 | CLI 二次确认并要求原因；删除任务目录和派生索引；不留下 tombstone/审计 | CLI 集成 |
| AC-028 | Docker Compose | 同一镜像运行常驻 Web 和按需 CLI，共享配置、任务、索引、脚本和 Vault 卷 | Docker E2E |

## 2. 容量门禁

| ID | 固定负载 | 通过标准 |
|---|---|---|
| PERF-001 | 50 个模拟 SSH 节点，每节点固定脚本和延迟，默认并发 10 | 10 分钟内完成；全部节点终态；无死锁或结果丢失 |
| PERF-002 | PERF-001 同负载 | 控制服务器 WFT 进程峰值 RSS < 1 GiB |
| PERF-003 | 任务历史和派生索引重建 | rebuild 后查询数、任务状态和问题数与权威目录一致 |

容量报告必须注明“模拟 SSH 节点”，不得描述为 50 台真实服务器认证。

## 3. CI 门禁

每次提交：

- Python 3.12 单元测试；
- 文件/Git/HTTP/AI 集成测试；
- FastAPI 页面和认证测试；
- Ruff 格式与静态检查；
- 类型检查；
- 依赖审计和 Git secret scan；
- Docker 镜像构建。

里程碑/发布：

- 完整端到端测试；
- PERF-001～003；
- Compose 部署冒烟测试；
- 文档命令逐条验证；
- 需求—验收追踪检查。

## 4. 明确不执行的测试

需求方确认 1.0 发布不包含：

- 100 MiB/1 GiB 等大输出压力测试；
- 磁盘写满故障注入；
- `kill -9` 等不可捕获进程中止故障注入；
- 真实 50 节点容量测试；
- HTTPS、备份、恢复、审计和旧数据迁移测试。

这些缺口必须写入发布说明，不得以单元测试或代码审查替代验证结论。

## 5. 里程碑关闭规则

一个里程碑仅在以下条件同时满足时关闭：

1. 对应 AC 自动化通过；
2. 文档和示例命令验证通过；
3. 没有未报告的规格偏差；
4. 提交测试证据并由需求方确认；
5. GitHub 子 Issue 关闭。
